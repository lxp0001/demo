# 任务 4.1｜测试设计

## 任务目标

依据任务 3.1～3.3 的设计文档设计测试用例，手动执行并发现老师提供的订单系统版本中的缺陷。本任务只发现问题，不修复。

## 技术与范围

- 被测对象：老师提供的订单系统（含若干缺陷，不提示数量和位置）；Python + FastAPI + SQLite。
- 设计方法：等价类、边界值、异常场景、状态转换。
- 范围：下单、查询订单、订单状态、模拟支付、重复提交。
- 用例要覆盖设计文档中的每条规则，每条规则至少有一个正例和一个反例；数量字段至少包含 0 和 1；设计文档规定了上限的，还要包含上限和上限加 1，没有规定的记为设计缺口，不自己编造。
- 不修改业务代码，不编写自动化测试（任务 4.2 完成）。

## 操作步骤

1. 阅读任务 3.1～3.3 的设计文档，列出所有可测试的规则，并标明来自哪份文档。
2. 设计用例表：编号、前置条件、输入、期望结果、依据。期望结果必须来自设计文档，不能来自运行结果。
3. 先自己手动执行（`/docs` 或 HTTP 客户端），记录实际结果，标出失败的用例。
4. 让 Agent 补充遗漏的用例，逐条判断：有设计依据的采纳，没有依据的拒绝并说明理由。
5. 对每个失败的用例写缺陷描述：现象、期望、实际。暂不定位原因。
