# 任务 6.1｜架构分析与决策记录

## 任务目标

从老师提供的订单系统代码中还原现状架构，找出架构问题，针对质量属性提出改进方案，并写成架构决策记录。

## 技术与范围

- 被测对象：老师提供的、结构混乱的订单系统（Python + FastAPI + SQLite）。
- 方法：画模块依赖图（手画加脚本辅助，具体工具以老师要求为准）、问题清单、备选方案比较、架构决策记录。
- 质量属性：可修改性、可测试性、可部署性。
- 本任务只分析和决策，不修改业务代码。
- 不做：微服务拆分、消息队列、云部署。

## 操作步骤

1. 阅读代码，列出模块和职责，画现状依赖图：谁导入谁、谁调用谁。
2. 找出架构问题：每条写证据（文件或依赖）、影响哪种质量属性、严重程度。
3. 为主要问题提出方案：至少两个备选，比较各自的好处和代价。
4. 让 Agent 评审你的依赖图和问题清单，只评审，不画图，不改代码；逐条判断是否采纳。
5. 写架构决策记录：背景、决策、备选方案、后果（好处和代价）。
