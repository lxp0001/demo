# 任务 6.2｜架构改造与可重复启动

## 任务目标

按架构决策记录小步重构订单系统，保持行为不变，并让项目能在干净环境中用命令启动；最后完成一次变更演练，检验改造效果。

## 技术与范围

- 基础：任务 6.1 的架构决策记录和老师提供的订单系统；第四阶段的全部测试作为安全网。
- 重构方向：分层清晰、依赖方向单一、支付等外部服务通过抽象接口接入（可替换）、配置外部化（环境变量或配置文件）、数据库可切换（SQLite 或 MySQL）。
- 小步：每一步之后运行全部测试，行为不变才能继续，失败立即回退。
- **命令启动（必做）**：README 写明启动命令；在新克隆的仓库中按命令启动成功；`GET /health` 返回 200。
- **Docker Compose（选做）**：编写配置，一键启动后端和数据库。
- 变更演练：老师给出事先不告知的变更，完成并记录改动范围。
- 不做：微服务拆分、消息队列、云部署。

## 操作步骤

1. 把架构决策记录拆成小步计划：每一步做什么、风险、如何证明行为不变、怎么回退。
2. 逐步重构，每一步运行全部测试，记录结果；失败就回退，并写明原因。
3. 写出依赖规则（如接口层不直接依赖数据访问层），并用脚本检查。
4. 配置外部化，补全启动命令，在新克隆的仓库里验证命令启动和 `/health`。
5. 完成变更演练，记录改动范围和反思；选做 Docker Compose。
