# 阶段八教师用:项目说明书补充(不发给学生)

## 一、各项目的可能变更(中途或答辩时使用)
| 项目 | 可选的变更 |
|---|---|
| P1 | 新增「套餐预约」(一次预约多个服务),或支持跨门店调班 |
| P2 | 增加「按小区分拣」的规则,或部分成员免等待 |
| P4 | 增加「紧急工单」的独立流程 |
| P5 | 增加「志愿时长证明」的导出格式 |
| P8 | 换一批文档,调整低置信度的转人工阈值,或更换模型 |

变更按改动范围和测试结果评价,沿用第六阶段的办法。

## 二、评审关注点
| 项目 | 重点 |
|---|---|
| P1 | 门店间数据隔离的测试、排班变动对已有预约的处理、并发抢同一时段 |
| P2 | 并发下不超卖、截单边界、汇总的准确性 |
| P4 | 权限矩阵的测试、状态流转的合法性、超时升级的幂等 |
| P5 | 导入的校验与去重、时长计算的边界、个人信息在报表中的处理 |
| P8 | 评估集的设计、答案与引用的一致性、低置信度的兜底、提示注入的处理 |

## 三、P8 评估集的保密做法
- 老师准备一份**对学生保密**的评估集,覆盖:文档内能回答的、文档内没有的(应当拒绝)、含夹带指令的文档片段、容易混淆的相近问题。
- 学生提交的系统用保密评估集测试,看准确率、拒绝是否恰当、引用是否正确、提示注入是否被抵御。
- 评分看评估方法是否严谨、失败是否被诚实记录、兜底是否有效,**不以准确率的绝对值为主要依据**。

## 四、准入提醒
- 每个项目的需求方都要先看《给需求方的说明函》。
- 说明函中关于数据、保密、成果使用权和责任的表述,是按常见情况写的,正式使用前建议请学校相关部门审阅。
- C 级项目(P1)在设计评审后再确认;评审时重点看小组能否完成,完不成就降级。
- 同一个蓝本可以让多个小组分别对接不同的需求方,需求会自然不同。
- AI 类项目要先确认学生能否稳定使用模型服务,以及额度和费用由谁承担。
