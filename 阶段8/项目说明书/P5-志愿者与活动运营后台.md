# P5 志愿者与活动运营后台

- 难度:B
- 典型需求方:公益组织、社团

## 背景
组织需要导入志愿者名单,安排排班,在活动现场签到,并生成统计报表。

## 用户与角色
- 组织者:导入名单、创建活动和排班、导出报表。
- 志愿者:查看自己的排班、签到。

## 增量里程碑
- **M1**:名单导入与去重,可命令启动,有健康检查和 CI。
- **M2**:活动与排班。
- **M3**:签到。
- **M4**:统计与导出。

## 非平凡逻辑(用「一句话需求能否直接生成正确答案」来检验)
导入时的去重与合并规则(同一人在不同表里姓名写法不一致),以及志愿时长的计算规则(迟到、早退)。

## 主要难点
- 导入数据的质量:校验、去重、纠错。
- 排班冲突。
- 个人信息保护。
- 报表的口径。

## 需要向需求方澄清的问题
1. 同一个人在不同表里写法不一致时,以什么为准?
2. 迟到和早退怎么计算时长?
3. 报表给谁看,需要哪些字段?
4. 哪些个人信息不能出现在报表里?
5. 名单一般有多大规模?

## 数据与保密提示
- 只收集完成功能所必需的信息;开发和测试使用脱敏的假数据。
- 使用外部 Agent 或模型服务前,先确认需求方是否允许把代码或数据交给外部服务。
- 不提交密钥和真实个人数据;不直接操作需求方的生产环境数据。

## 评价关注点
- 需求是否经过需求方确认,假设是否被验证。
- 设计是否在实现之前,测试是否先行。
- 变更是否有影响分析。
- 质量证据:测试、依赖规则、安全检查、性能基线、命令启动。
