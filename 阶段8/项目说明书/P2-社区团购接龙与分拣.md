# P2 社区团购接龙与分拣

- 难度:B 到 C
- 典型需求方:团长、社区商户

## 背景
团长发起接龙,成员下单,到点截单,系统汇总成采购单和分拣单。

## 用户与角色
- 团长:创建接龙、设置限量和截单时间、查看汇总。
- 成员:下单、修改、取消。
- 商户(可选):查看采购单。

## 增量里程碑
- **M1**:商品与接龙,可命令启动,有健康检查和 CI。
- **M2**:下单与限量并发。
- **M3**:定时截单与汇总。
- **M4**:分拣单与导出。

## 非平凡逻辑(用「一句话需求能否直接生成正确答案」来检验)
限量商品在并发下单时的扣减和拒绝规则,以及截单时间点前后订单的归属。

## 主要难点
- 并发下不超卖。
- 截单前后的边界处理。
- 汇总的准确(取消、修改后的数据)。
- 定时任务的可靠性。

## 需要向需求方澄清的问题
1. 截单之后还能修改订单吗?
2. 缺货时已下的订单怎么处理?
3. 一个成员能不能代他人下单?
4. 分拣单需要什么格式?
5. 一次接龙一般有多少人参与?

## 数据与保密提示
- 只收集完成功能所必需的信息;开发和测试使用脱敏的假数据。
- 使用外部 Agent 或模型服务前,先确认需求方是否允许把代码或数据交给外部服务。
- 不提交密钥和真实个人数据;不直接操作需求方的生产环境数据。

## 评价关注点
- 需求是否经过需求方确认,假设是否被验证。
- 设计是否在实现之前,测试是否先行。
- 变更是否有影响分析。
- 质量证据:测试、依赖规则、安全检查、性能基线、命令启动。
