# P8 知识库问答助手(AI)

- 难度:B 到 C
- 典型需求方:学院办公室、物业、社团等常见问题多的单位

## 背景
需求方有一批文档(规定、流程、常见问题)。用户提问,系统给出答案并标明来源段落。答错或答不出时转人工。

## 用户与角色
- 用户:提问并查看带来源的回答,可对回答反馈。
- 管理员:导入和更新文档、查看反馈和日志、处理转人工。

## 增量里程碑
- **M1**:文档导入与切分,可命令启动,有健康检查和 CI。
- **M2**:检索与问答(带引用)。
- **M3**:评估集与质量评估。
- **M4**:反馈、人工兜底与日志。

## 非平凡逻辑(用「一句话需求能否直接生成正确答案」来检验)
检索与回答的质量控制:什么时候回答、什么时候拒绝并转人工(依据检索结果的相关性)、如何保证答案来自文档。

## 主要难点
- 答案是否真来自文档,引用是否准确。
- 检索质量与评估。
- 文档更新后的一致性。
- 文档内容里夹带指令(提示注入)。
- 成本和延迟。

## 需要向需求方澄清的问题
1. 哪些问题不能让机器回答?
2. 答错的后果是什么?
3. 文档多久更新一次?
4. 哪些文档含有不能外传的内容?
5. 转人工的渠道是什么?

## AI 类项目的统一要求
| 要求 | 说明 |
|---|---|
| 评估集先行 | 先定义「什么算对」,收集带标准答案的样本,记录准确率和失败案例;评估集的一部分对学生保密 |
| 降级与兜底 | 模型失败、超时、低置信度时有明确的退路 |
| 人工确认 | 高影响的结果必须由人确认,不能自动生效 |
| 成本和延迟预算 | 设定调用上限、超时和重试策略 |
| 隐私与保密 | 向外部模型发送数据前取得需求方同意并脱敏;不提交密钥 |
| 防提示注入 | 把用户输入和文档内容当作不可信数据,输出不直接执行 |
| 可追溯 | 记录提示词版本、模型版本、输入和输出摘要 |
| 不做高风险决策 | 不用于录取、评分、处罚、医疗建议等 |

## 数据与保密提示
- 只收集完成功能所必需的信息;开发和测试使用脱敏的假数据。
- 使用外部 Agent 或模型服务前,先确认需求方是否允许把代码或数据交给外部服务。
- 不提交密钥和真实个人数据;不直接操作需求方的生产环境数据。

## 评价关注点
- 需求是否经过需求方确认,假设是否被验证。
- 设计是否在实现之前,测试是否先行。
- 变更是否有影响分析。
- 质量证据:测试、依赖规则、安全检查、性能基线、命令启动。
