# 任务 7.1｜任务拆解与规格说明

## 任务目标

把新功能拆成小任务，写规格和验收标准，先写测试，再让 Agent 分步实现，并用对照实验比较“一句话交给 Agent”和“先拆解规格再实现”两种使用方式。

## 技术与范围

- Agent 工具：自选，请在提交文档里写明所用工具。
- 功能 A：菜品搜索与分页，例如 `GET /api/dishes?q=&page=&page_size=`。
- 功能 B：订单统计，统计本人的订单数和总金额，可按状态统计；只能看到自己的数据。
- 对照实验只针对功能 A：两个分支，一个用一句话需求直接交给 Agent，一个先拆解、写规格和测试，再分步实现。
- 对照指标：隐藏验收测试通过数、改动的文件数和行数、返工次数；耗时选填。
- 项目约定文件：写明技术栈、目录结构、常用命令、编码约定和禁止事项；文件名以所选工具的要求为准。
- 不做前端改动，不做工具之间的比较。

## 操作步骤

1. 阅读两个功能的需求，把每个功能拆成 3 到 6 个小任务，每个写清完成标准和验证方式。
2. 写项目约定文件（可参考 `02-项目约定文件示例.md`）。
3. 功能 A，方式一：在一个独立分支上，用一句话需求直接交给 Agent，记录过程和结果。
4. 功能 A，方式二：在另一个分支上，先写规格和验收测试，再分步交给 Agent，每一步审查改动。
5. 比较两种方式的指标，写出结论和局限。
6. 功能 B：用方式二完成，并对照需求自检，特别检查访问控制。

- 提交项目约定文件、两个分支的代码、功能 B 的代码，以及测试运行记录。
- 展示对照实验的数据和结论，并说明结论的局限。
