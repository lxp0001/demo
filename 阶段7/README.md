# 第七阶段｜Coding Agent 的系统使用：食堂订单系统

前六个阶段，学生一直在“受控地”使用 Coding Agent。本阶段把这些经验系统化：怎么拆任务、怎么写规格、怎么审查、怎么验证、怎么安全地授权。学生可以自选 Agent 工具，课程按产出评价，不按工具评价。本阶段仍以食堂订单系统为载体，难度与第四至第六阶段相当。

| 任务 | 学习重点 | 本任务完成时能看到什么 |
|---|---|---|
| 7.1 任务拆解与规格说明 | 拆解需求、验收标准先行、项目约定文件、对照实验 | 拆解与规格文档、项目约定文件、两种使用方式的对照数据 |
| 7.2 审查、验证与协作安全 | 审查 Agent 改动、验证闭环、权限边界、使用复盘 | 审查记录、验证闭环说明、权限与安全清单、使用复盘 |

三个新功能分配如下：

| 功能 | 用在哪 | 说明 |
|---|---|---|
| 菜品搜索与分页 | 任务 7.1（对照实验） | 同一个功能，用两种方式各做一次，比较结果 |
| 订单统计 | 任务 7.1（规格先行） | 只统计本人的订单；需要检查访问控制 |
| 订单取消与退款状态 | 任务 7.2（审查对象） | 老师提供 Agent 生成的实现，学生审查、验证、修复 |

## 学生完成方式

每项任务保留“独立草案 → Agent 的回应 → 运行证据 → 人工判断与修订”。本阶段有三条硬要求：

- **验收标准先行**：先写验收测试和完成标准，再让 Agent 实现。
- **用数据说话**：比较两种方式时，用测试通过数、改动范围、返工次数，不凭感觉。
- **验证要能发现问题**：说“测试通过了”不够，要说明这些测试能不能发现刚才找出的那类问题。

## 范围说明

- Agent 工具自选：请在提交文档里写明所用工具，以及项目约定文件、权限配置的具体做法（不同工具的名称和写法不同）。
- 只在练习项目的独立分支上使用 Agent，不对任何他人的系统使用。
- 不做前端改动。不做工具之间的优劣比较，对照实验只比较“使用方式”。
