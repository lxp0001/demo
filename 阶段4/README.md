# 第四阶段｜测试与调试：食堂订单系统

本阶段在第三阶段的食堂订单系统上继续，围绕“怎样知道它是对的，错了怎么办”依次完成测试设计、自动化测试和缺陷定位。老师提供含缺陷的订单系统版本，学生要依据设计文档找出缺陷，并证明自己的测试和修复是有效的。本阶段不提示缺陷的位置，难度高于前三个阶段。

| 任务 | 学习重点 | 本任务完成时能看到什么 |
|---|---|---|
| 4.1 测试设计 | 从设计文档推导用例、等价类、边界值、异常场景 | 一份测试用例表，以及在缺陷版本中发现的问题 |
| 4.2 自动化测试 | pytest、测试隔离、替身、覆盖率、测试有效性 | 在正确版本通过、在缺陷版本失败的自动化测试 |
| 4.3 调试与缺陷定位 | 复现、假设、断点与日志、回归测试 | 缺陷报告、修复和每个缺陷对应的回归测试 |

## 学生完成方式

每项任务保留“独立设计 → Agent 补充与回应 → 运行证据 → 人工判断与修订”。Agent 可以补充用例、生成测试代码、解释报错，但要由学生判断：用例是否有依据，断言是否真的检查了期望，修复是否真的消除了缺陷。

三个任务在同一个代码项目上依次完成：任务 4.2 使用任务 4.1 的用例，任务 4.3 使用老师提供的另一个缺陷版本，并要求每个缺陷留下回归测试。每项任务的填写模板可作为学习记录；代码、测试、截图和日志按任务 README 中的清单一同提交。

## 范围说明

阶段四只测试和调试订单系统的后端：下单、查询订单、订单状态、模拟支付和重复提交。前端测试为选做。不做性能测试、安全测试和持续集成，这些留到后面的阶段。
