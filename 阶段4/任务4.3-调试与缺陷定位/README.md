# 任务 4.3｜调试与缺陷定位

## 任务目标

在老师提供的另一个含缺陷的订单系统版本中定位并修复缺陷，按“复现、缩小范围、定位、修复、回归”的流程记录，并为每个缺陷留下回归测试。

## 技术与范围

- 被测对象：老师提供的第二个缺陷版本（缺陷与任务 4.1、4.2 的不同，不提示数量和位置，其中包括需要用调试器才能看清的逻辑缺陷和一个金额精度问题）。
- 调试手段：日志、VS Code 的 Python 调试器（断点、查看变量）、浏览器开发者工具、pytest。
- 每个缺陷必须有一个“先失败、修复后通过”的回归测试。
- 至少一个缺陷要用断点或日志证据定位，不能只靠阅读代码猜测。
- 不重写模块，修复要尽量小，并说明为什么没有影响其他行为。

## 操作步骤

1. 复现：为每个现象写出最小的复现步骤。
2. 提出至少两个假设，写明如何验证；先写假设，再让 Agent 辅助。
3. 用日志、断点或二分缩小范围，记录每次验证的证据和结论，包括被排除的假设。
4. 先写一个会失败的回归测试，再修复，确认测试通过。
5. 运行全部测试做回归，写缺陷报告。
6. 反思：哪些缺陷任务 4.2 的测试本来能发现，哪些不能，为什么。

## AI 提问参考

> 我在订单系统里观察到这个现象：（现象和复现步骤）。我的假设是：（假设）。请不要直接给出修复代码，先告诉我应该用什么日志或断点来验证这个假设，以及还有哪些我没有想到的可能原因。

- 提交修复后的 `backend/`、新增的回归测试、断点或日志截图。
- 展示缺陷报告、被排除的假设，以及“先失败后通过”的回归测试运行结果。
