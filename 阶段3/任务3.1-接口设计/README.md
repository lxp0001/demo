# 任务 3.1｜接口设计

## 任务目标

为食堂点餐设计提交订单接口并写成接口文档，让 Agent 先评审再实现，并对照文档逐项验收。

## 技术与范围

- 后端：Python + FastAPI + SQLite，在任务 2.3 的基础上扩展。
- 接口：`POST /api/orders` 提交订单（一次可包含多个菜品和数量），`GET /api/orders/{id}` 查询订单。
- 请求只传菜品编号和数量，总价由后端按数据库中的价格计算。
- 要设计的出错情况：格式错误、数量不合法、菜品不存在、菜品已售罄、订单不存在，状态码和 `code` 自己定并写明理由。
- 订单暂时放在一张 `orders` 表中，菜品列表用一个文本列保存 JSON，任务 3.2 再拆分。
- 不增加支付、重复提交处理和登录。

## 操作步骤

1. 自己写接口文档：路径、方法、请求体、成功响应、出错响应和业务规则。
2. 让 Agent 只做评审，指出问题和遗漏，不写代码；逐条记录采纳或不采纳，以及理由。
3. 修订文档后，让 Agent 按文档实现，先看计划，再动手。
4. 用 `/docs` 对照文档，验收成功情况和每一种出错情况。
5. 对比自己的文档与 `/openapi.json`，不一致时判断改文档还是改代码，并写明理由。

## AI 提问参考

> 评审阶段：请审查 `docs/api.md` 里的下单接口设计，只指出问题和遗漏，不要修改文件，也不要写代码。重点检查路径和方法是否合理、状态码是否恰当、出错情况是否完整、字段是否明确。
>
> 实现阶段：请在 `backend` 目录按 `docs/api.md` 实现 `POST /api/orders` 和 `GET /api/orders/{id}`。总价由后端按数据库中的价格计算，使用参数化查询，不要使用 ORM，不要增加文档以外的接口。动手前，先告诉我你计划新增或修改哪些文件。
