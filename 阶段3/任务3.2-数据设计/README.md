# 任务 3.2｜数据设计

## 任务目标

把订单拆成订单表和订单明细表，设计表之间的关系并画出关系图，并证明改造后对外接口的行为不变。

## 技术与范围

- 数据库：SQLite + `sqlite3`，不使用 ORM。
- 表：`orders`（订单）和 `order_items`（订单明细），明细通过外键关联订单和菜品。
- 明细保存下单时的单价；每次连接数据库都要打开外键检查。
- 下单时在同一个事务里写入订单和明细。
- 使用重建数据库的脚本，不做数据迁移；接口文档和前端都不修改。
- 不增加复杂统计和多对多关系。`.db` 文件不提交。

## 操作步骤

1. 回答旧设计的问题：想查哪个菜点得最多？菜品改价，历史订单要不要变？每个订单有几道菜怎么算？菜品被删除后，订单指向谁？
2. 设计表、列、主键和外键，画数据关系图，写明为什么这样拆、为什么保存单价、哪些写入需要事务。
3. 让 Agent 实现：重建数据库的脚本和接口改造，先看计划，再动手。
4. 用任务 3.1 的验收项重新验收一遍（回归验收）。
5. 核对数据：改菜品价格后历史订单金额不变；让明细写入失败，检查订单表没有残留；检查外键是否生效。
