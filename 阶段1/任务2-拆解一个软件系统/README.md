# 任务2｜拆解一个软件系统：模块与结构

## 任务目标

选择一个软件系统（可沿用任务1的产品，也可换一个），从整体角度识别它由哪些主要部分组成，以及这些部分如何协作。关注“系统地图”，暂不深入某一功能的完整过程。

## 观察提示

可以从用户看得见的页面、不同使用者、主要功能区域入手；如果有教师提供的系统结构图或案例说明，可据此推测后端服务、数据存储和外部服务。标注“亲眼观察到”“材料说明”“我的推测”，不要把推测写成确定事实。

## 操作步骤

1. 确定系统和观察范围，先独立画第一版系统地图。
2. 列出主要使用者和模块，用依据区分观察事实与推测。
3. 请 AI 提供检查问题或其他解释，不让 AI 替你直接决定架构。
4. 对照界面、操作记录或教师材料核验，修订图示并保留修改理由。
5. 写出仍无法确认的内部信息。

## AI 提问参考

> 我在拆解【系统名】。以下是我观察到的页面、功能和资料：【粘贴】。请帮助我把它们归纳成“使用者—前端/页面—后端服务—数据/外部服务”的候选模块图。每条推断请标明依据或不确定性；不要声称知道未公开的内部实现。

## 提交

完成《01-系统模块与结构图.md》，含系统范围、模块清单、结构图、依据与推测、AI 核对和总结。
