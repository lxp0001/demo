# 任务 5.1｜安全检查

## 任务目标

对带用户的食堂订单系统做安全检查：列出威胁，用测试证明漏洞确实存在，再修复，并证明修复有效、没有破坏其他功能。

## 技术与范围

- 系统：Python + FastAPI + SQLite，由老师提供的练习系统，包含简化的登录（`POST /api/login` 返回令牌，请求用 `Authorization` 头携带）和两个测试用户。
- 检查范围：访问控制（能否访问他人的订单）、输入校验、SQL 注入、敏感信息（密钥、日志和错误信息）、对前端数据的信任。
- 方法：威胁清单 + 证明漏洞的自动化测试（pytest）+ 修复 + 回归。
- 只在老师提供的练习系统和自己的机器上检查，不对任何他人的系统做检查。
- 不做：渗透扫描工具、HTTPS 配置、密码存储的密码学细节。

## 操作步骤

1. 梳理资产和入口：哪些数据重要，哪些接口接受外部输入。
2. 写威胁清单：每条写威胁是什么、可能怎样被利用（一句话）、后果、预期的防护。
3. 为每条威胁设计证明测试：断言“系统应当拒绝”，在练习系统上运行应当失败，失败说明威胁存在。
4. 让 Agent 补充遗漏的威胁，并评审你的修复方案；逐条判断是否采纳。
5. 修复后重新运行：证明测试通过，全部回归测试通过；说明为什么这样修复有效，以及是否带来新的问题或取舍。
