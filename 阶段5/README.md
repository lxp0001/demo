# 第五阶段｜安全与性能：食堂订单系统

本阶段在第四阶段的食堂订单系统上继续。老师提供一个增加了简化登录和用户的订单系统，其中含有安全漏洞和性能问题。学生要自己发现问题，用测试或测量证明问题存在，再修复并证明修复有效。本阶段不提示问题的位置，难度与第四阶段相当。

| 任务 | 学习重点 | 本任务完成时能看到什么 |
|---|---|---|
| 5.1 安全检查 | 威胁清单、访问控制、输入校验、注入、敏感信息、先证明再修复 | 威胁清单、证明漏洞的测试、修复与回归记录 |
| 5.2 性能与并发 | 先测量再优化、基线、瓶颈定位、并发正确性 | 优化前后的对比，以及并发下订单仍然正确的测试 |

## 学生完成方式

每项任务保留“独立草案 → Agent 补充与回应 → 运行证据 → 人工判断与修订”。本阶段有两条硬要求：

- **先证明，再修复**：没有可重复的测试或测量，不能说问题存在，也不能说已经修好。
- **先测量，再优化**：不凭感觉判断哪里慢；每次只改一处，改完重新测量，并确认没有破坏正确性。

Agent 可以补充遗漏的威胁、解释概念、评审方案，但要由学生判断：威胁是否真实、修复为什么有效、优化是否真的达到目标。

## 范围说明

- 所有安全检查只在老师提供的练习系统和自己的机器上进行，不对任何他人的系统做检查或压测。
- 不做：渗透工具的使用、真实攻击、HTTPS 配置、分布式压测、缓存中间件、负载均衡和生产监控。
- 并发部分默认使用 SQLite；需要时可以切换为 MySQL（老师提供配置），作为选做。
