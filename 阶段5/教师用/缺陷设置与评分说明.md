# 阶段五教师用:问题设置与评分说明(不发给学生)

## 一、练习系统的准备
- 在订单系统上增加**简化的登录和用户**:`users` 表、`POST /api/login` 返回令牌、请求用 `Authorization` 头;订单带 `user_id`;预置两个测试用户(A 和 B),各有若干订单。学生不需要实现登录。
- 为菜品增加**库存数量**,下单时扣减(用于 5.2 的并发场景)。
- 提供一个**正确版本**(所有问题已修复),用于验证学生的测试与优化没有破坏功能。
- 数据库访问层做成可配置:默认 SQLite,可切换 MySQL。方言差异清单:占位符(`?` 与 `%s`)、自增类型、外键与事务写法。
- 切换 MySQL 建议用 Docker:提供 compose 配置,学生只需启动,不需要自己编写。这会让 Docker 的引入比原先设想(第六阶段之后)提前一些,请先确认学生的 Windows 环境能运行 Docker Desktop;不能的,保留 SQLite 部分即可。
- **伦理提醒**:明确告知学生只在练习系统和自己的机器上检查与压测。

## 二、5.1 练习系统中的安全问题
| 编号 | 问题 | 设计依据 | 应被什么测试发现 |
|---|---|---|---|
| S1 | 用户 B 能查询用户 A 的订单(没有检查订单归属) | 访问控制 | 用 B 的令牌查询 A 的订单,应被拒绝 |
| S2 | 按名称搜索菜品时,SQL 由字符串拼接而成 | 3.2 参数化要求 | 构造包含引号的搜索词,应被正常处理 |
| S3 | 某个接口接受并使用了前端传来的价格 | 3.1 总价由后端计算 | 传入更低的价格,总价应仍按数据库计算 |
| S4 | 日志中输出了完整的令牌 | 敏感信息 | 检查日志输出 |
| S5 | 出错时把内部错误堆栈返回给了前端 | 敏感信息 | 触发错误,检查返回内容 |
| S6 | 数量没有上限,可以提交极大的订单 | 输入校验 | 提交超大数量,应被拒绝 |

## 三、5.2 练习系统中的性能与并发问题
| 编号 | 问题 | 如何显现 |
|---|---|---|
| P1 | 按用户查询订单列表时缺少索引 | 数据量增大后 P95 明显变慢 |
| P2 | 查询订单详情时,对每条明细单独查询菜品(逐条查询) | 明细越多越慢 |
| P3 | 调用支付的等待时间设置过长 | 支付变慢时拖慢整体 |
| C1 | 下单扣减库存时,先检查再扣减,不是原子操作 | 并发下单会超卖 |
| C2 | 同一请求标识的检查与写入不是原子的 | 并发重复提交会产生多个订单 |

## 四、评分建议
- **5.1 自动检查**:学生的证明测试在练习系统上应失败(至少发现若干问题)、在正确版本上应通过;再运行教师的隐藏安全测试,检查学生修复的版本。
- **5.2 自动检查**:用教师的负载脚本测学生优化后的版本,P95 低于阈值,错误率为 0;并发正确性测试通过。
- **AI 评价**:威胁清单和测量计划是否在使用 Agent 之前完成、假设与证据是否对应。
- **人工评价**:现场解释一个漏洞为什么存在、一个优化为什么有效。
- 学生提出的、不在上表中的合理威胁或瓶颈,经确认后同样给分。
