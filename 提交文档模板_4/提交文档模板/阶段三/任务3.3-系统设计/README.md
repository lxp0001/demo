# 任务 3.3｜系统设计

## 任务目标

设计包含支付的完整下单流程：划分模块职责，画出顺序图，设计并实现支付失败、支付超时和重复提交的处理，并对照设计验收。

## 技术与范围

- 后端：Python + FastAPI + SQLite，在任务 3.2 的基础上扩展。
- 订单状态：待支付、已支付、支付失败。
- 支付使用老师提供的模拟支付服务，可配置为成功、失败或超时，不接入真实支付。
- 要设计的异常：菜品已售罄、支付失败、支付超时（订单保持待支付）、重复提交（用请求标识识别）。
- 模块职责至少包括：订单接口、订单业务、数据访问、支付客户端。
- 不做自动对账、消息队列，分层和架构风格留到第六阶段。

## 操作步骤

1. 梳理正常流程和订单状态，划分模块职责，写明每个模块负责和不负责什么。
2. 列异常清单：每个异常发生在哪一步、订单状态怎么变、返回前端什么、数据库里留下什么。
3. 画顺序图：正常流程和每个异常各一张。
4. 让 Agent 先用自己的话复述设计，确认无误后，先实现正常流程，再逐个实现异常。
5. 配置模拟支付，逐个场景验收；对照顺序图核对日志和数据，不一致时判断改设计还是改代码。
