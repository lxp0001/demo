# 任务 4.2｜自动化测试

## 任务目标

把关键测试用例写成可重复运行的自动化测试，保证测试相互独立，用替身模拟支付服务，并用缺陷版本检验测试是否真的有效。

## 技术与范围

- 测试工具：pytest + FastAPI `TestClient`，覆盖率用 `pytest-cov`。
- 隔离：每个测试使用独立的临时 SQLite 数据库（fixture）。
- 替身：支付服务用替身模拟成功、失败、超时，不调用真实的模拟支付服务。
- 范围：订单业务和接口。前端测试为选做（用 Vitest 测试已选件数的计算）。
- 有效性要求：全部测试在正确版本通过，在缺陷版本上至少有若干测试失败。
- 老师提供的测试集中有一个偶发失败的用例，需要找出原因并修复。

## 操作步骤

1. 从任务 4.1 的用例中选出要自动化的用例，按“准备—执行—断言”写出测试设计。
2. 设计 fixture：独立数据库、支付替身。写明每个测试如何做到不依赖其他测试。
3. 让 Agent 生成测试代码，先看计划。逐个审查：断言是否真的检查了期望（不只是状态码，还包括数据库和订单状态）。
4. 在正确版本上全部通过；在缺陷版本上运行，记录哪些测试失败、对应哪个缺陷。
5. 运行覆盖率，解释哪些代码没有被覆盖以及原因，并补充必要的用例。
6. 找出偶发失败用例的原因（如共享状态、顺序依赖），修复并说明如何验证已经稳定。
