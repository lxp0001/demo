# 任务 5.2｜性能与并发

## 任务目标

先测量再优化：为订单系统建立性能基线，压测并定位瓶颈，优化后证明有效，并验证并发下订单仍然正确。

## 技术与范围

- 压测工具：Locust。
- 数据库：默认 SQLite；并发正确性部分可选切换到 MySQL（老师提供 Docker 配置和可切换的数据库访问层）。
- 被测对象：老师提供的、含性能问题的订单系统；菜品增加了库存数量，下单时扣减。
- 指标：响应时间的平均值和 P95、每秒请求数、错误率。
- 场景：查询订单详情、查询订单列表、下单；并发场景包括同时下单和同一请求标识重复提交。
- 不做：缓存中间件、分布式部署、负载均衡、生产监控。

## 操作步骤

1. 写测量计划：场景、并发用户数、持续时间、要看的指标、成功标准（你的假设）。
2. 用 Locust 建立基线并记录结果。
3. 提出瓶颈假设并验证（日志耗时、逐段计时、数据库查询分析），记录被排除的假设。
4. 每次只优化一处，重新测量，记录前后对比，并检查是否破坏了正确性。
5. 验证并发正确性：并发下单不超卖，同一请求标识重复提交只产生一个订单；发现问题后修复并回归。选做：切换 MySQL 对比并发表现。
