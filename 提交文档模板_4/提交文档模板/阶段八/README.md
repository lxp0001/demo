# 第八阶段｜综合实战：真实项目

最后一个阶段，学生以小组（建议 3 到 4 人，个人贡献必须可追溯）承担一个**真实项目**：有真实的需求方和用户，需求不会像练习系统那样清楚。学生要把前七个阶段的方法放进一个完整项目里，从澄清需求一直做到交付和答辩。

项目来源（经老师审批后确定）：

- **校内真实需求方**：学院、社团、实验室、信息部门等。
- **企业导师项目**：企业提供的、范围可控的小项目。
- **开源项目贡献**：有维护者、接受外部贡献、有贡献指南和许可证的项目。

| 任务 | 学习重点 | 本任务完成时能看到什么 |
|---|---|---|
| 8.1 项目启动与设计 | 需求澄清、范围协议、设计包、风险与合规、里程碑、设计评审 | 与需求方确认的需求、设计包、风险与合规清单、评审记录 |
| 8.2 迭代实现、交付与答辩 | 迭代与反馈、变更管理、质量证据、交付清单、答辩 | 可交付的项目、变更日志、交付清单、复盘与答辩 |

## 学生完成方式

每项任务保留“独立草案 → Agent 的回应 → 运行证据 → 人工判断与修订”。本阶段有四条硬要求：

- **与需求方确认**：范围和验收标准要得到需求方的确认，并保留记录。
- **保护数据和保密**：使用外部 Agent 前，先确认需求方是否允许把代码或数据交给外部服务；不提交密钥和真实个人数据。
- **用证据说话**：设计在实现之前，测试先行，变更有影响分析，质量有证据。
- **个人贡献可追溯**：提交记录、评审记录和个人问答共同证明每个人做了什么。

## 范围说明

- 不直接操作生产环境的数据；只收集必要的个人信息，并说明用途。
- 开源贡献要遵守项目的贡献指南和许可证；**是否被合并不作为评分依据**，因为这取决于维护者。
- 技术栈以项目需要为准，经老师审批；但必须做到：能用命令启动、有自动化测试、有健康检查或等价的启动确认。
- 不做：脱离需求方的自拟需求、超出能力范围的大型系统。
