# 任务 8.2｜迭代实现、交付与答辩

## 任务目标

按里程碑迭代实现真实项目，处理真实发生的需求变更，满足交付清单，向需求方交付并完成答辩。

## 技术与范围

- 迭代：每次迭代交付可演示的增量，向需求方演示并记录反馈。
- 变更：记录真实发生的需求变更，先做影响分析，再决定接受、拒绝或推迟。
- 质量：全部测试、依赖规则检查、安全检查与修复、性能基线、干净环境命令启动。
- 交付：满足交付清单（见 `02-交付清单.md`），并写运行手册。
- Agent：记录使用日志，遵守保密与数据边界。
- 开源项目：按贡献指南提交合并请求，并回应评审意见；是否合并不作为评分依据。
- 答辩：演示、老师现场的变更演练、个人问答。
- 不做：直接操作生产环境数据。

## 操作步骤

1. 按里程碑迭代。每次迭代前更新计划；迭代后向需求方演示并记录反馈。
2. 出现需求变更时，先做影响分析（范围、设计、测试、风险），再决定做不做、怎么做，并写入变更日志。
3. 每次迭代结束运行全部检查：测试、依赖规则、干净环境启动。
4. 完成安全检查和性能基线，记录发现与处理。
5. 整理交付：运行手册、已知问题；逐项自检交付清单。
6. 答辩：演示项目，完成老师现场的变更演练，回答个人问题；写团队和个人复盘。

- 提交可运行的项目、变更日志、质量证据、Agent 使用日志和个人贡献记录。
- 展示向需求方演示的反馈、变更的影响分析与结果、交付清单的逐项证据。
