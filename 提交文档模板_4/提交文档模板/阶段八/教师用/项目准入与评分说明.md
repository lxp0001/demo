# 阶段八教师用:项目准入与评分说明(不发给学生)

## 一、项目准入检查表
| 检查项 | 要求 |
|---|---|
| 需求方 | 有明确的联系人,愿意参与访谈、演示和验收反馈 |
| 范围 | 范围可控,小组能够完成;可以拆成可演示的增量 |
| 数据与隐私 | 不涉及真实敏感数据,或已脱敏并获得授权;只收集必要信息 |
| 保密与 Agent 使用 | 需求方明确是否允许把代码或数据交给外部 Agent 服务;不允许的,要有替代办法 |
| 技术栈 | 老师认可;能命令启动、能自动化测试 |
| 开源项目 | 接受外部贡献;有贡献指南和许可证;维护者知情 |
| 风险 | 不涉及生产环境数据的直接操作 |

## 二、需要提前告知需求方的内容
- 这是教学项目,学生是学习者,交付质量会有限制。
- 需求方需要参与访谈、演示和验收反馈,并对范围做出确认。
- 数据安全和保密的约定,包括是否允许学生使用外部 Agent。
- 学生不会直接操作生产数据。

## 三、风险与应对
| 风险 | 应对 |
|---|---|
| 需求方失联或反馈慢 | 事先约定反馈频率;老师协助联络;必要时调整范围 |
| 范围膨胀 | 范围协议和变更日志;每次变更要做影响分析 |
| 数据泄露或保密违规 | 准入时确认;学生使用脱敏数据;检查提交内容 |
| 开源贡献无人理会 | 合并与否不作评分依据;看过程和对评审的回应 |
| 个别学生搭便车 | 提交记录、评审记录、个人问答共同核实 |
| 项目太难或太简单 | 准入时评估;允许经老师批准后调整范围 |

## 四、评分建议(可按需要调整)
| 部分 | 参考权重 | 看什么 |
|---|---|---|
| 需求与设计(8.1) | 25% | 需求确认记录、假设与确认、设计是否在实现之前、风险与合规 |
| 迭代与变更(8.2) | 25% | 迭代反馈记录、变更日志的影响分析和决定理由 |
| 质量与交付(8.2) | 25% | 交付清单的证据、命令启动、测试、安全与性能证据 |
| 答辩与个人 | 25% | 演示、变更演练的改动范围、个人问答、个人贡献记录 |

## 五、自动检查与答辩
- **自动检查**:在新克隆的仓库里按 README 命令启动,检查健康接口;运行测试;运行依赖规则检查;检查仓库中是否有密钥。
- **变更演练**:老师根据学生的项目现场给出一个小的变更,按改动范围和测试结果评价;沿用第六阶段的办法。
- **个人问答**:对每位组员提问其负责的部分和关键决策。
- **需求方反馈**:作为参考,不作为唯一依据,避免因需求方因素影响评分。
- **开源项目**:合并请求是否被合并不作为评分依据。

## 六、还需要准备的内容
- 给需求方的说明函(项目性质、期望、数据与保密约定)。
- 设计评审表和答辩评分表。
- 小组协作规则模板(分支、评审、分工记录)。
- 若技术栈统一,可准备交付清单的检查脚本。
- 对学生的保密和伦理提醒(使用外部 Agent 前先确认是否允许)。
