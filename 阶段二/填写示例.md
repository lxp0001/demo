# 阶段二填写示例｜食堂菜品“番茄炒蛋”

示例展示填写方法，尤其是如何保留自己的预测、证据与修改理由。请用自己运行项目得到的结果替换示例。

## 任务 2.1：页面

- 我的草图：顶部显示“食堂点餐”和已选 0 件；列表每行显示名称、价格和按钮。
- 我的验收标准：`inStock=false` 时显示“已售罄”，加入按钮不可点击；点击有库存菜品后件数从 0 变成 1。
- AI 的建议：增加完整购物车。我拒绝了，因为本任务只要求件数，购物车会增加未设计的状态和交互。
- 验收证据：运行 `npm run build`；打开页面，分别点击有库存和已售罄菜品并记录结果。

## 任务 2.2：接口联调

- 我的接口草案：`GET /api/dishes` 返回菜品数组，`GET /api/dishes/1` 返回一条菜品；不存在的 id 返回 404。
- 联调前预测：前端使用 `inStock`，而后端可能使用 `in_stock`，字段名有可能对不上。
- 实际证据：在 Network 查看响应，发现后端返回 `in_stock`；页面库存状态显示错误。
- 修订：明确由后端统一返回 `inStock`（或由前端集中转换），重新请求并确认页面正确显示。

## 任务 2.3：数据库

- 我的表设计：`id INTEGER PRIMARY KEY`、`name TEXT NOT NULL`、`price REAL NOT NULL`、`in_stock INTEGER NOT NULL`。
- 我的预测：接口地址不变，因此前端不用为存储方式变化而重写。
- 验证：建库脚本运行两次，数据库仍只有预期的初始记录；将“番茄炒蛋”价格从 12 改成 13，刷新页面后显示 13。
- 我的判断：页面随数据库变化，说明查询链路已连接数据库；还应检查后端查询代码，排除页面仍使用假数据的可能。
